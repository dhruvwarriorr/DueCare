Supabase-managed tables are read for authorization but are not owned or recreated by application migrations. The local test cluster provides synthetic Auth tables with RLS enabled and no runtime read policies, matching Supabase’s protection. A private SECURITY DEFINER function owned by the privileged migration role performs the narrow session/Google-identity lookup; runtime has only execute access and cannot directly read Auth tables. The production entry point has no test-login switch; browser-test authentication is installed only by `tests/e2e_server.py`.

## Checks performed

- **18 Pytest cases passed** against PostgreSQL 18, including enforced RLS, native identity/session authorization, eligibility hook behavior, actual ECDSA signature checks, refresh concurrency, timing/status rules, revisions, and pagination/idempotency.
- **3 Vitest/React Testing Library checks passed** for academic fields, single batch, roll-number formatting, timing controls, and browser-timezone-independent IST conversion.
- **2 Playwright workflows passed** through the Next.js gateway and real FastAPI/PostgreSQL path. Coverage includes onboarding, lab subject/timetable, task edits while completed, reload persistence, reopening, calendar, mobile overflow, saved dark theme, subject editing/deletion, sign-out, forged writes, an online quiz changing from due to missed in an idle open view at closing, and credential-free public HTML.
- **Fresh migration → downgrade → reapply passed** on a separate disposable database. Assertions confirm eight application tables and all six owner-scoped tables with enabled/forced RLS. The initial migration freezes its schema definition rather than importing future application models.
- **Production Next.js build, TypeScript, ESLint, Ruff lint/format checks passed.** Node 24 was used for the production build; Python 3.13 was used for API checks.
- **Production dependency audit reports zero vulnerabilities.** Full npm audit currently reports five high findings along the development-only Next.js ESLint → fast-glob → micromatch → braces chain, centered on `GHSA-vfj7-8cjw-p6xm`. The installed braces release has no compatible patched upgrade reported by npm; its proposed fix downgrades Next.js ESLint configuration to an incompatible older major. No forced downgrade was applied. This development-tooling finding remains recorded for upstream remediation; do not pass untrusted glob patterns into lint tooling.
- FastAPI's current TestClient adapter emits an upstream HTTPX deprecation warning. Tests pass; future test-tool upgrades should address it. No runtime warning suppression was added.
- An unconfigured production API entry point returns process health and a structured database-setup error without enabling synthetic authentication.

CI configuration is included in `.github/workflows/verify.yml` (renamed from `phase1.yml` in Phase 2). It performs local verification with a disposable PostgreSQL service and no hosted secrets. The GitHub-hosted workflow itself has **not** run, because nothing was committed or pushed.
